# Восстановление профилей OpenCode в Herdr

Локальный TUI-плагин `opencode.herdr.session` дополняет установленную Herdr
интеграцию `herdr-opencode`: она сообщает состояние агента и выбранную сессию,
а этот плагин добавляет `resume_argv` с профилем. Нужен Herdr 0.9.2 или новее
и OpenCode V2. Подключение обоих плагинов задано в `config/cli.json`.

Функции `oc-gp` и `oc-ds` в `home/.bash_aliases` передают через
`OPENCODE_HERDR_RESUME_ARGV` команду восстановления. Поскольку это функции
интерактивного Bash, Herdr запускает соответственно:

```text
bash -ic 'oc-gp "$@"' -- --session <id>
bash -ic 'oc-ds "$@"' -- --session <id>
```

Кавычки в примере — синтаксис оболочки для отображения: в самом массиве argv
апострофов нет. Bash должен загружать `~/.bash_aliases` из `~/.bashrc`.
Без переменной восстанавливается прямой запуск `opencode --session <id>`;
другие параметры прямого запуска не сохраняются автоматически.

Плагин сообщает корневую сессию выбранного поддерева, повторяет отклонённые
отчёты и раз в пять секунд обновляет команду. Он использует ту же пару
`herdr:opencode` / `opencode`, что установленная интеграция, не отправляет
состояние и не использует `seq`, чтобы не нарушать порядок её state-отчётов.
Штатная интеграция версии 13 не отправляет `resume_argv`; совместимость с
другими её версиями нужно проверять при обновлении.

В конфиге Herdr необходимо `[session] resume_agents_on_restore = true`.
Для проверки используйте отдельную именованную сессию Herdr: откройте в ней
панели с `oc-gp` и `oc-ds`, проверьте `agent_resume.argv` в сохранённом
`session.json`, остановите и восстановите эту сессию. Проверьте, что каждая
панель вернулась к своей сессии и профилю. Мок сокета не подтверждает реальный
рестарт Herdr или WSL.

```sh
node --test config/herdr/session.test.mjs config/herdr/session.tui.test.mjs
```

Диагностика: `${XDG_STATE_HOME:-$HOME/.local/state}/opencode-herdr/session.jsonl`.
Правки в снимке не устанавливаются на хост автоматически.
